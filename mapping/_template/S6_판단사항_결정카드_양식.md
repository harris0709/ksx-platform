# S6 판단 사항 결정 카드 — 양식 (사항 1건 = 1장)

S6 검증 중 **구현안내서와 다르게 하거나, 안내서가 정하지 않은 것**, 그리고 **위반의 처리 방식**을 정하는 자료다(IMPIX D-1~D-4).
승인 회의에서 **한 장씩 순서대로** 보여 주고, 결정을 받은 뒤 다음 장으로 넘어간다.
결정은 `S6_승인기록.md`의 "승인 요청 사항" 표 결정 열에 옮겨 적고, 안내서를 고쳐야 하면 "구현안내서 반영" 표에도 적는다.
결정으로 생성물·매핑·계획이 바뀌면 다시 생성 → 물질화(S5) → `validate --seed`·`validate`를 다시 돌려 숫자를 갱신한 뒤 다음 카드로 간다.

위반은 **원인이 있는 곳**에서 고친다. 지식 그래프를 직접 고치지 않는다(안내서 9.4).

| 원인 위치 | 예(IMPIX) | 처리 |
|---|---|---|
| S4 생성기 | 같은 이름 속성의 코드 그룹(S4R-04), 코드·단위 IRI 인코딩(S4R-05) | 생성기 수정·회귀 시험, S4 사후 변경 — 판단 여지가 없으면 카드 없이 보고 |
| 확장 정의 | 표준에 없는 단위(D-2) | 확장정의서 등록 |
| S2 매핑 | 원천에 없는 표준 필수 라인(D-3) | 명세 추가 |
| 운영 방식 | 정상 운영인데 품질 셰이프가 잡음(D-4) | 셰이프 한정(계획 매개변수) |
| 원천 데이터 | 실제 오류 | 원천 책임자(`ksxq:owner`) 정정 요청 |

S6에서 판단 사항이 되는 것과 근거를 모으는 방법:

| 유형 | 예(IMPIX) | 근거를 모으는 방법 |
|---|---|---|
| 검증 범위 | D-1 그래프별 vs 합집합 검증 | 그래프별 검증 시 참조 클래스 오탐 건수, 그래프 간 참조 건수(S5 D-2) |
| 값 위반(코드·단위) | D-2 단위 목록에 없는 단위 13건 | 위반 값이 어휘에 있는지(IRI 표기 비교 — `%2F` 등), 원천 표기, 이전 단계 확장 후보 기록 |
| 구조 위반 | D-3 라인 0개 창고 4건 | 표준 본문 근거(예: 7.1 `struct[1..N]`), 원천에 해당 데이터가 있는지 |
| 의미 위반(품질) | D-4 지시 등록 전 LOT 15건 | 원천 행 실측(공장·요일·시각 분포), 현업 운영 방식 확인(이전 단계 기록) |
