## 승인 요청 사항

### 1. S2에서 새로 정한 확장(Extension)

표준 명사에 해당 속성이 없어 확장한 항목이다. 이름이 같은 표준 속성이 있으면 재사용했다(ksx 속성). 새 속성은 `impix:` 이름공간을 쓴다.

| 확장 | 원천 | 이유 |
|---|---|---|
| LotExt.LotOriginType(+코드 그룹 생산·구매·이관)·VendorID·VendorLotNumber | mes.tb_lot, erp.tb_mm_gr 등 | 구매 자재 LOT·이관 LOT를 표준 로트로 등록(표준 LotType은 고정형이라 출처는 확장) |
| ProductionOrderExt.ProductionOrderStatusCode (+코드 그룹 5) | erp.tb_pp_mo.mo_stat | 생산지시 진행 상태 |
| AlarmExt.AlarmSeverityCode (+코드 그룹 3) | mes.tb_alarm.alm_lvl | Q-SC04-17 중대 알람 |
| CustomerPartyMasterExt.CustomerGroupCode (+코드 그룹 OE·AM) | erp.tb_sd_cust.cust_grp | 출하 우선순위·수요예측 정확도 |
| EquipmentStateExt.StateStartDateTime·StateEndDateTime | mes.tb_eqp_stat.st_dtm·ed_dtm | 가동율·MTTR(표준 설비상태에 구간 시각 없음) |
| GoodsReceiptExt.PurchaseDocumentNumber·Sequence·LotID | erp.tb_mm_gr.po_no·po_seq·vend_lot | 납기준수율, 입고 LOT 추적 |
| GoodsIssueExt.InventoryTransactionDate·ProductionOrderID·Sequence | erp.tb_mm_gi, qms.qm_scrap | 출고·폐기 처리일, 투입 오더 |
| ProductIncomingExt.ProductionOrderID·Sequence | erp.tb_pp_rcpt.mo_no | 생산계획 달성율(오더 기준) |
| TraceParameterExt.LotID | mes.tb_param_val.lot_no | 파라미터 이상 → 불량 LOT |
| EquipmentParameterExt.LCL·UCL | mes.tm_param.lcl·ucl | 관리한계(규격한계와 별개) |
| CorrectiveActionRequestExt.OccurrenceDate·InspectionResultID | qms.qm_vend_ncr | 월별 부적합, 수입검사 → NCR |
| AvailableInventoryExt.MaterialRequirementQuantity | erp.tb_pp_mat_chk.req_qty | 자재충족율 분모(표준 RequiredQuantity는 정수라 새 이름) |
| 표준 그룹 하위 코드: EQ-008 진동 과다, ItemLargeClass CSM, EquipmentLargeClass CST·CLN·ASM·PKM | 알람·품목군·설비그룹 | 회사정의 그룹에만 추가(고정형 그룹은 금지) |

### 3. 주요 구조 판단

- **로트는 출처 4곳에서 만든다(A안, 2026-10-23 결정).** 로트를 참조하는 10개 원천 컬럼이 모두 표준 로트를 외래키로 가리키도록 했다.

  | 명세 | 원천 | LOT 수 | 출처 |
  |---|---|---|---|
  | `mes/Lot` | mes.tb_lot | 155 | 생산(PRODUCTION) |
  | `erp/Lot_material` | erp.tb_mm_gr | 169 | 구매(PURCHASE) |
  | `erp/Lot_legacy` | erp.tb_mm_stock_lot(rcv_dt < 2026-08-01) | 5 | 이관(LEGACY) — 기초 재고 |
  | `erp/Lot_shipped` | erp.tb_sd_dlv(lot_no < E260921) | 88 | 이관(LEGACY) — MES 도입 전 출하 |

  공급사 LOT 번호는 품목 간에 겹친다(번호 75개 → 품목 LOT 169개). 그래서 구매 LOT의 식별자는 `공급사LOT_품목`(변환 `mat_lot`)으로 만들고, 원래 번호는 LotExt.VendorLotNumber에 남긴다.
  원천 데이터로 확인한 결과 4개 출처 사이에 겹치는 LOT은 없다. 입고·수입검사·LOT 재고·출하·클레임·폐기·파라미터·설비상태·투입·착완공의 LOT 참조는 모두 417개 LOT 안에서 해소된다(없는 LOT 0건).

- 생산실적은 MES 일 집계(`tb_prod_rslt`)가 아니라 LOT 착·완공(`tb_trk_in/out`)에서 매핑한다. 일 집계는 S6 검증 기준값으로만 쓴다.
- 알람 1행(발생·해제)은 이벤트 2행(ON·OFF)으로 펼친다. 설비상태는 구간(시작·종료) 1행이다.
- 품목 원장은 ERP다. MES `tm_item`은 제외한다(동기화 사본, Q001 중복 원인).
- 수주유형 N·S는 DOMESTIC으로 병합한다. 보수용 구분은 고객군(AM)으로 남는다.
- IQC 불량 I-APP·I-DIM은 대분류(APP·DIM)만 매핑하고 상세는 비운다.

### 4. 실습 중 반영한 수정 (2026-10-23, 사용자 PC 커밋 596fdec)

- 사용여부 적재 필터 3건 추가: 공장·부서 `use_yn = 'Y'`, 설비파라미터 `use_flag = 'Y'`. 제외 사유("적재 필터")와 계획을 일치시켰다.
- 약어 사전 `SO: [SalesDocument, Sales]` 보강 → 수주일(SalesDate ← so_dt)이 자동 매칭으로 바뀌고 계획의 수작업 1줄을 지웠다(결정론 71.6% → 71.9%, 검토자 수정 2.0% 유지).
- 실습에서 설비파라미터 필터에 없는 컬럼(`use_yn`)을 쓴 사례가 있어, automap이 필터 컬럼의 존재를 검사하도록 보강했다(+회귀 시험).

- 엔진 보강: 식별자 조합(concat)에 쓰인 컬럼도 단독 매칭을 계속 받도록 고쳤다. 이전에는 판매계획의 품목·고객, 생산계획의 품목, 수주라인의 단가가 빠져 있었다. 선택 속성이라 완료 기준에 걸리지 않았던 누락이다.

### 5. 다음 단계로 넘기는 과제

- 확장 단위 후보 2건(N·m, cc/min): ksxgen 단위그룹 확장(다음 버전)까지 S3에서 원천 단위 문자열을 보존한다.
- S3(dbt 스테이징)는 명세의 `from`·`transform`·`code`·`uom`을 SQL로 옮긴다. 변환 어휘는 `s2_plan.yaml` 머리말을 따른다.
- S1 품질 이슈 '상' 11건은 S3 정제 규칙으로 처리한다(예: 품목코드 대소문자·공백 → `upper_trim`, 단위 ea·개 → EA).
- 승인 후 명세 status를 `approved`로 올린다(계획에서 일괄 적용).
