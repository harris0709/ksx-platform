## D-1. 개발·검증용 GPU 조달 — 어디서, 어떤 등급을, 어떻게 쓰고 정리하나

> **범위:** S9 착수 준비 — 개발·검증용 GPU **대여** 결정이다(측정 도구 마련). **운영 GPU는 S9 검증 측정으로 모델이 정해진 뒤 별도 결정 카드로 정한다**(요구사항 → 모델 → GPU 순서).

### ① 원천 (안내서·이전 단계가 정한 것)

- `S8_승인기록.md` 넘긴 과제: PC 벡터 색인(승인 조건, S9 착수 시), 재정렬 사용 여부(GPU·응답 시간 목표 결정 후, D-3), LLM·재정렬용 GPU 서버(개발 24GB, 검증 48GB 이상).
- `LLM서비스_아키텍처_하드웨어사양.docx`(인프라 전달본): 개발 GPU 24GB급, 검증 48GB급, 운영은 검증 측정 후 결정.
- PC 실측(S8): bge-m3 임베딩을 CPU로 돌리면 메모리 8.6GB/9.7GB를 써 PC가 느려짐 → max-batch-tokens 2048로 낮춤. CI(CPU)에서 재정렬은 질의당 약 50초, 임베딩 서버와 함께 띄우면 메모리 부족(OOMKilled).

## D-2. 주 LLM(구현안내서 D6) — 후보군·측정 절차·선정 규칙

> S9 정식 착수(2026-11-27)에 맞춰 다시 쓴 판. 이 카드는 **후보군과 고르는 방법**을 정한다. 최종 모델은 평가 세트(D-3)·응답 목표(D-6)가 정해지고 MCP 도구가 준비된 뒤 **측정 결과로** 정하고 이 카드에 기록한다.

### ① 원천 (안내서가 정한 것 — 12.1, 표 39 D6)

1. 라이선스: 상업 이용·사내 배포·미세조정 파생물 배포가 허용되는 모델만 **운영 후보**. 비상업(NC)은 **비교 연구용**으로만.
2. 한국어·도구 호출 평가: 업무 질의서 **200건**으로 의도 분류 **≥ 90%**, 도구 선택 **≥ 90%**, 인자 스키마 적합 **≥ 99%**.
3. 하드웨어 적합: 목표 동시 사용자에서 **첫 토큰 지연 p95 ≤ 2초**(부하 시험).
4. 서빙: vLLM(`--enable-auto-tool-choice --tool-call-parser <계열 파서>`), 게이트웨이 LiteLLM(내부 주소만). 미세조정(LoRA)은 1차 구축에서 하지 않음 — 질의 생성 미달 시에만.
5. 장비: D-1 — 개발 24GB, 검증 L40S 48GB(운영 GPU는 선정 모델로 나중에 산정).

## D-4. 1차 MCP 도구 범위 — 서버·도구·데이터 원천

### ① 원천

- 안내서 12.2 표 30: 서버 6개 — ksx-ontology(Fuseki·Ontop), ksx-ledger(원장 읽기 복제본), ksx-kpi(원장·Fuseki), ksx-timeseries(**시계열 저장소**·Fuseki), ksx-docs(Qdrant), ksx-action(Decision Engine, 제안만).
- 안내서 12.4: 전용 도구(산식 고정) → 저장 질의 → 생성 질의 순으로 쓴다. 출력 `{rows, provenance, scope, truncated}`, 범위는 토큰 클레임에서 주입.
- 안내서 6장(S4): 도구 스키마는 어휘만으로 정해지는 ontology·ledger만 S4에서 생성, **KPI·시계열·문서 검색·Action 도구는 S6~S9에서 작성**.
- S8 인계: 속성 그래프 `ksx_graph`의 경로 탐색(계보·영향·BOM)을 cypher로 — ksx-ontology에서 쓴다.

### ② 현황

| 서버 | 도구 스키마 | 데이터 원천 | 상태 |
|---|---|---|---|
| ksx-ontology | 있음(S4) — get_noun_card, sparql_query, get_lot_genealogy, find_affected_orders, explain_inference | Fuseki·Ontop·AGE·명사 카드 | 구현 없음 |
| ksx-ledger | 있음(S4) — sql_query, get_struct, get_bom_tree | 원장(PostgreSQL) | 구현 없음 |
| ksx-kpi | 없음 | S1 KPI 정의서 34종(산식은 **원천 기준 SQL**) | 원장 기준 산식으로 옮겨야 함 |
| ksx-timeseries | 없음 | **별도 시계열 저장소 없음** — 원장 `TraceParameter`·`EquipmentParameter`·`Alarm` + S7 추론(R-020 스펙아웃) | 구현 없음 |
| ksx-docs | 없음 | Qdrant 4종(S8) | 구현 없음 |
| ksx-action | 없음 | Decision Engine(**S10에서 만듦**) | 없음 |

### ③ 선택지

| 안 | 내용 | 영향 |
