| 규칙 | 범위별 트리플 |

- 공장을 넘는 관계 622건: 정상 업무 흐름이다(P2 완제품 LOT ← P1 하우징 LOT, P1 실적 → P2 완제품 수주). 관계는 주어 쪽 공장 그래프에 들어가므로, 한 공장만 보는 사용자는 상대 공장의 노드나 그 공장에서 출발한 관계를 보지 못한다. 이런 질의를 어떻게 다룰지는 ③ MCP 도구에서 정한다(공장을 넘는 추적은 두 공장 권한이 모두 있을 때만 허용).
- 새 노드 중 공장이 섞인 것 4건(R-100 납기 리스크 이벤트): 이벤트 노드가 P1 LOT과 P2 수주를 함께 가리킨다. 같은 순위의 공장이 둘 이상이면 이름순 앞 공장(P1)으로 둔다(`scope.narrow`).
- 범위를 못 정한 것 0건.

## 5. PC 반영 절차

1. `.env`에 `KSX_BATCH_PASSWORD=<암호>` 추가
2. `python -m ksxload ddl` — 관리자 계정으로 `ksx_batch` 생성, RLS 적용
3. Ontop 재시작 — 접속 계정이 `ksx_batch`로 바뀜
4. `python -m ksxkg validate` → `infer` → `sync` 다시 실행 — 새 이름의 그래프로 교체
